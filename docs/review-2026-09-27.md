### P0 — 已修复：更新图表先删旧图，任一后续失败都会造成用户内容丢失

- **文件:行号**：`tc-office.js:101-138,201-252`、`taskpane.js:1037-1054,1530-1552`（`main taskpane.js:848-858,927-938,970-980`）。
- **问题**：原实现先删除 PowerPoint/Excel 旧形状，再插入并保存新状态；插入、SVG 回退、重命名或 settings 保存失败时，旧图已经不可恢复。
- **复现**：更新已插入图表，在 SVG 插入或 `settings.saveAsync` 阶段制造失败（低版本 API、断网加载资源、Office 返回错误）。
- **修复**：改成 `snapshot → insert pending → identify → persist → tag/rename → delete old` 的提交顺序；提交前失败清理临时新图，提交后清理失败则保留新旧两图并给出可恢复提示。
- **最小模式**：

  ```js
  const prepared = await adapter.snapshot();
  const pending = await adapter.insert(prepared);
  await adapter.persist(prepared, pending);
  await adapter.renameAndTag(prepared, pending);
  await adapter.deleteOld(prepared, pending); // 最后一步
  ```

- **最小模式**：

## 与 think-cell 的功能差距（按用户价值排序）

1. **真正的 PowerPoint ↔ Excel 持久数据链接与 Data Links 管理器 — L**  
   当前 `TCCHART1:` 是快照，Excel 定义名称也只在本工作簿、任务窗格打开时刷新。think-cell 支持数据链接的单次更新、自动更新、回退、断链恢复和切换来源。Office 加载项下最可行的完整方案是“用户明确选择的 OneDrive/SharePoint 文件 ID + Microsoft Graph range API + 本地缓存 + 冲突/撤权/离线状态”；需要登录同意和服务层。Custom Functions 适合 Excel 公式，不能直接驱动 PowerPoint 形状更新；`localStorage`/共享 WebView 存储也不能作为可靠跨应用、跨设备链接。参考：[think-cell 数据链接管理](https://www.think-cell.com/en/resources/manual/manage-data-links)、[Excel 数据链接](https://www.think-cell.com/en/resources/manual/exceldatalinks)。

2. **Excel 级嵌入式 Datasheet/slide workbook — L**  
   当前网格适合粘贴和轻编辑，但没有公式、区域拖拽、行列语义、Undo/Redo、Excel 快捷键。Web 加载项无法在 PowerPoint 中嵌入一个与 think-cell 等价的原生 Excel datasheet；近期最佳方案是强化任务窗格网格，并允许绑定当前 Excel 工作簿/OneDrive 工作簿；中期可用隐藏工作表或 companion workbook。参考：[think-cell 元素数据表](https://www.think-cell.com/en/resources/manual/element-datasheets)、[图表数据](https://www.think-cell.com/en/resources/manual/think-cell-charts)。

3. **图上直接操作与完整标签布局引擎 — L**  
   缺少拖动标签、锚点、引导线、轴范围、断轴位置、连接线和系列顺序的直接操作；也没有全局碰撞优化。当前 JSON 参数能表达部分结果，但编辑体验差距最大。

4. **跨图同比例尺（same scale）及断轴联动 — M/L**  
   引擎可以在单张 spec 内做比例和断轴，但没有选择多张 Office 形状、持久分组并在任一图变化后传播 scale/breaks。需要文档级 scale-group、批量扫描和事务更新。参考：[think-cell 坐标轴与同比例尺](https://www.think-cell.com/en/resources/manual/axes)。

5. **完整链接更新状态：待更新徽标、更新一次、自动、回退、备用来源 — L**  
   当前只有自动刷新/断链保留/重新链接，缺少用户可见的数据版本和可回退快照。

6. **甘特图编辑体验 — M**  
   Python 引擎已经支持自适应日期刻度、ISO 周/财年、一行多段、里程碑形状与标签位置、底纹、括号、分隔线、越界箭头和状态列；主要差距在 UI：大多数能力只能写高级 JSON，没有表格式日历编辑、拖动锚点、模板日历和批量行格式。参考：[think-cell 甘特图](https://www.think-cell.com/en/resources/manual/gantt)。

7. **图例、标签、CAGR、差异箭头的交互和自动避让 — M**  
   已能渲染这些对象，但定位主要由规则/参数决定；缺少拖动手柄、自动避让、与数据单元格绑定的文本字段、针对更新的保留布局策略。

8. **Mekko/瀑布的专用 datasheet 语义 — M**  
   输出类型已覆盖，但没有 think-cell 式 100%= 行、分段宽度/高度语义提示、可拖连接线、小计识别和交互式重排。

## 视觉规范差距

- **字号**：`py/tccore/style.py:28-31` 为标题 14 pt、标签 9 pt、小字 8 pt。标题/标签接近咨询图表常用范围，但 8 pt 在投影和高密度 Gantt 上偏小。建议正文/图例默认下限 9 pt，小字仅用于来源并允许按画布自适应。
- **颜色对比**：`style.py:15-17` 的最浅蓝 `#B9D5EC` 和 `OTHER #D9D9D9` 在白底上边界弱；`FG_MUTED #8C8C8C` 配 8–9 pt 时也容易在投影中消失。建议对浅系列加 0.5–0.75 pt 边线或纹理，并允许色盲安全主题。
- **标签文字色**：`style.py:88-96` 用非线性的简单亮度阈值 0.55 选择黑/白字，不是 WCAG 相对亮度/对比度算法；中间色可能选错。建议分别计算与 `#FFF/#1A1A1A` 的对比度，选更高者并设置最低阈值。
- **图例与间距**：当前图例和小标签优先追求紧凑，长中文系列在窄任务窗格/4:3 幻灯片容易压缩。建议增加文本测量后的换行/分栏和 4–6 pt 最小对象间距，不要只截断。
- **标题归属**：当前标题默认画进图表。think-cell 常与幻灯片文本框共同排版；建议提供“图内标题/沿用幻灯片标题/无标题”三种明确模式，避免重复标题和可用绘图区缩水。
